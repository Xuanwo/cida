# 翻译图层

2026-09-27 确认并实现，取代 PR #2 的截图原位替换与独立图片窗口（截图翻译回到把文字带进面板）。状态见 [`boards/translation-layer.html`](../boards/translation-layer.html)，依据见本节末。

## 一、是什么

- 在任何应用里原位翻译外文：临时翻一段，或一直翻一个 pane（消息列表、网页正文、文档区）。译文盖在原文上，新出现的内容自动翻译。
- 不影响应用原有的功能：图层是一层不接收鼠标的透明窗口，点击、滚动、选中、输入都照常落到应用上；应用的界面、数据与复制出来的文字都不变。原文随时可看（§四）。
- 文字只取自应用的辅助功能树：准确，带每一块的位置，不识别屏幕。读不到文字的内容（图片、游戏、远程桌面）不在图层的范围内，用截图翻译（⌥S）。
- 只翻译成「我的语言」（`spec/settings.md` §三）：原文已经是我的语言的块原样保留、不发请求，由本机语言识别判断（简体与繁体中文算同一种）；设置里的写法认不出是哪种语言时全部发送，模型原样返回的块不画。写回复仍用面板。
- 新增的设置只有一个可录制的快捷键（§二）；译文用面板同一个模型服务与翻译提示词。体验随权限分两级（§三、§五），由用户是否授予屏幕录制决定，不另设开关。

## 二、⌥D：翻一段，或一直翻一个区域

- 第三个可录制的全局快捷键，默认 ⌥D（挨着 ⌥S），在设置「唤起」组「截图翻译」下方一行，见 `spec/settings.md` §五；三个快捷键不能相同。菜单栏菜单在「截图翻译」下方有同一个动作「翻译图层 ⌥D」。
- 按下后，指针所在屏幕整块罩上纸雾（同截图框选：`surface-paper` 72%；系统为暗色外观时 `text-ink` 45%），屏幕保持实时、不冻结。屏幕上方一枚提示胶囊：字标 +「点击：翻译这一段 · ⇧ 点击：一直翻译这个区域 · Esc 取消」；指针停在一个 pane 上时，开头加上它的适用范围，如「example.dev · …」「Slack · …」，pane 已在一直翻译时后半句换成「⇧ 点击：不再翻译这个区域」。配置期间其他两个全局快捷键不响应。
- 所有一直翻译、在这块屏幕上可见的 pane 从纸雾里托起，样式同截图选区：纸雾在 pane 处留空（向外 6pt），圆角 `radius-card` 8，面板同款阴影与 `panel-edge` 描边；里面照常显示译文。
- 指向屏幕上任何窗口：指针下的 pane 在纸雾里留空并画 1.5px 虚线 `accent` 框；其中指针下的那一段再画一个细虚线框，垫一层 `accent-soft`。
- **点击**：只翻这一段。配置立刻关闭，这一段的译文盖在原文上，它的应用切到前台。这一段离开屏幕、文字变化，或按 Esc，译文就消失；什么都不记住。同一时刻只有一段这样的译文。
- **⇧ 点击**：一直翻译这个 pane；配置不关闭，这个应用切到前台、窗口移到最前（被挡住的 pane 完整露出并托起），键盘仍在配置上，可继续 ⇧ 点击别的 pane。在已托起的 pane 上 ⇧ 点击就不再翻译它。只悬停不切换前台。⏎ 完成，前台停在最后点选的应用；Esc 或右键放弃这次的修改，已经切换的前台不还原。
- 取 pane 的方法：辅助功能在指针处命中的元素，文字、链接、图片、按钮这类小元素往上找，第一个宽高都够大（至少 200×120pt）且含有至少两段文字的容器；找不到时取第一个够大且含有文字的容器。不按角色判断：Slack 的消息区只是一个普通分组，不是列表或滚动区域。内容比滚动区域高时，pane 是那个滚动区域。输入框、较小的文本输入区与菜单不算 pane。
- 选中的是 pane 本身，按辅助功能里的角色、DOM class 或标识符和它在窗口里的相对位置记住：窗口移动、缩放，切换频道后仍是同一个 pane；位置差得太远就不认，宁可不翻也不翻错。
- 适用范围：pane 在网页区域里时，按「应用 + 网站域名」记住，域名取自网页区域的 `AXURL`：同一网站的其他页面、其他标签页与窗口都生效，别的网站不受影响；网页里找不到同一个 pane 时这一页不翻译。pane 不在网页区域里时，按应用记住，套用到这个应用的每个主窗口。Slack 这类 Electron 应用的网页域名固定，效果与按应用相同，浏览器也不另设规则。不提供「这个浏览器里所有网页都翻译」：整站翻译用浏览器自带的网页翻译。
- 没有辅助功能权限时，按下快捷键只请求这一项权限（同「选中文字」），不进入配置。Chromium / Electron 应用第一次被指向时先打开它们的辅助功能树（`AXManualAccessibility`；Chrome 不认它时用 `AXEnhancedUserInterface`，只对带 Chromium 渲染进程的浏览器设置），约 2 秒后可读，期间提示胶囊显示「正在读取 <应用名>…」。读不到文字的应用，提示胶囊显示「<应用名> 里读不到文字，可以用截图翻译 ⌥S」。

## 三、显示

按块替换，译文画在原文块的位置上，字号取原文一行的高度（约 1/1.3），字体用系统字体；译文比原文长时先换行、再缩小字号（最小 8pt），不裁字；8pt 也放不下时这一块保留原文。

- 一块是只由文字、链接、图片与列表符号组成的最小容器，也就是一个段落：Slack 一条消息的正文、网页的一段、一个标题、一个列表项、表格或列表的一格。原生应用里上下排列、互不共享一行、中间没有链接的几段文字各算一块。块里的链接文字（@提及、网址、频道名）以 ⟦n⟧ 占位发给模型，回来后原样放回，只翻译其余文字。
- 文字全部在链接或按钮里的块不翻译：发送人、时间、表情回应、「N 条回复」、附件名、导航链接都是界面文字。Chromium 放在视图外、只有 1pt 高的虚拟行不读。
- 整篇文档放在一个文本区里的（TextEdit、备忘录一类的原生文本视图）：按换行分成段落，每段的位置由文本区按字符范围给出。
- 请求：一个 pane 里需要翻译的段落编号成 JSON 一次发出（每次最多 40 段、12000 字），回复按编号对应；少一个编号或有空译文就算这批失败。同一段原文只翻译一次（按原文缓存，所有 pane 共用）。
- 已授予屏幕录制：底色与字色取自原文块的画面（最多的颜色是底，与底亮度差最大的是字），译文看起来像应用本身的文字。
- 未授予屏幕录制：没有画面可取，译文画在纸片上：`surface-paper` 底、`text-ink` 字、`radius-chip` 圆角、1px `panel-edge` 描边，比原文块左右各宽 8pt、上下各高 3pt；系统为暗色外观时改为 `text-ink` 底、`surface-paper` 字。
- 新出现的块先显示原文，译好后整块一次换上（`motion-height-ms` 交叉淡入），不逐字出现。
- 状态胶囊：pane 右下角，只在有块等待翻译时出现：字标 +「翻译中 · N 条」，全部译完后消失。请求失败时改为「翻译失败 · 点按重试」并停留，点按即重试；还没有模型服务时为「还没有模型服务」。这是图层里唯一接收点击的地方。
- 开启「减弱动态效果」时，淡入淡出直接到位。

## 四、查看原文

- 指针在一块译文上停 300ms，这一块淡出（`motion-height-ms`）露出原文；指针移开即恢复。点击与选中文字始终落在原文上。

## 五、滚动与变化

- 辅助功能里块的位置与 pane 的位置每 50ms 读一次；读到变化，或 pane 上出现滚轮事件，就算内容在动。
- 已授予屏幕录制：只捕获 pane 所在的窗口（60 fps），逐帧按行比较 pane 区域的画面得出位移，译文跟着内容移动。一帧移动超过 pane 高度，或内容整体换掉（切换频道、翻页），译文淡出。图层可见期间 macOS 菜单栏会显示录屏指示，这是系统行为。
- 未授予屏幕录制：内容一动译文就淡出。
- 两级共用：内容停下 150ms 后重新读 pane 的段落，按新位置显示并翻译新露出的段落；静止时每秒也重读一次，接住新消息。
- pane 被别的窗口挡住的部分不画；应用隐藏、最小化或窗口移到其他桌面时整层隐藏。窗口移动、缩放时 pane 与图层跟着窗口。
- 屏幕录制权限的授予或撤销在下一次显示时生效，不需要重新选择 pane。

## 六、不做的事

- 不改应用的界面或数据：不向应用注入内容，不模拟点击或按键，不读剪贴板。
- 不翻译输入框里正在写的内容，不识别屏幕文字。
- pane 外不显示任何东西（配置时的纸雾与提示胶囊除外）。

## 可行性依据（2026-09-26 实测）

- 辅助功能：Slack 4.52 接受 `AXManualAccessibility`，约 2 秒后文字与位置可读；按坐标取元素约 4ms；读 3 个元素的位置约 0.4ms。Chromium 里块的位置在滚动时每 150–170ms 更新一次，值比画面晚约一帧；没有滚动通知，只能轮询。
- 逐帧跟随（有屏幕录制）：60 fps 捕获一个 Chrome 窗口，按行比较画面估计位移，6 段滚动的累计位移与实际滚动量完全一致；滚动开始后 37–57ms 画面里出现位移，捕获本身不到 1ms，每帧比较约 3–6ms；只在一帧移动超过一屏时拒绝判断。图层窗口不出现在捕获画面里。
- 真实 Slack 工作区（2026-09-27，只读）：打开辅助功能树后整个窗口约 940 个节点，全量读取 50–75ms。消息区是 `p-message_pane` 分组，在其中任一点命中都返回它的滚动容器，再往上一层就是它；左侧频道列表命中返回列表本身。每条消息是一个角色描述为「message」的元素（约 30–75 个节点），正文在 `p-rich_text_section` 里，被 @提及与链接拆成 1–8 段文字与链接；发送人、时间、回应、回复数、附件都在各自的链接或按钮里。
- 同一套规则、不做任何应用适配（2026-09-27，VM）：Safari（WebKit）认出标题、段落（含 3 段、7 段的混排链接）、列表项与表格格子，导航与只有链接的段落被跳过，pane 为网页区域；TextEdit 为一个文本区，按换行分出 3 段，按字符范围取位置可用；Finder 列表与系统设置（SwiftUI）按格子分块，pane 分别为列表与滚动区域。整窗读取 7–151ms。唯一的规则缺口是列表符号，已并入「段落可含的元素」。
- 尚未验证：真实 Slack 滚动时辅助功能位置的更新频率（按同一 Chromium 内核推断与 Chrome 相近）；原生 AppKit 应用的位置更新频率。
