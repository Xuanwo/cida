# 设置

2026-09-23 在 Proposal 上确认，取代 Settings 单板与 Settings Row 组件；2026-09-25「模型」改为 AI 助手配置（`spec/configuration.md`）；2026-09-27 加入「翻译图层」后单页在 14 寸屏上放不下（886pt，可用 874pt），改为四个标签页。状态见 [`boards/settings-states.html`](../boards/settings-states.html)。

## 一、窗口与标签

- 标准标题栏窗口（⌘, 或菜单栏「设置…」），宽 560 固定；紧凑标题栏 40pt，标题是当前标签的名字（窗口本身的标题同步，「窗口」菜单与旁白读到的一致），与红绿灯同一中线；`bg` 底色，内容左右内缩 28（`space-window-x`）。
- 标题栏下是四个标签，按新用户需要的顺序：模型（用什么模型）· 动作（文字怎样转换）· 快捷键（怎么唤起、辞达能读什么）· 通用（应用本身）。每个标签 76 × 46，居中排列、间距 4：Lucide 图标 18（sparkles、pen-line、keyboard、sliders-horizontal）在上，名字 11.5 medium 在下，间距 3；当前标签 `surface-dim` 底、`radius-card`，图标 `accent`、名字 `text-primary`，其余图标与名字 `text-secondary`。标签栏下留 10，再一条 1px `border` 通栏分隔线。
- 打开设置回到上次看的标签（辞达退出前有效），第一次是「模型」；还没有模型服务时从面板打开设置直接到「模型」。
- 窗口高度随当前标签的内容；切换标签或展开提示词时顶边不动、窗口用 150ms（`motion-height-ms`）ease-out 向下展开或向上收起（reduced motion 时直接到位），超过屏幕可见高度时停在可见高度、内容在窗口内滚动。
- 标签里按组排列：组标题 12 semibold `text-control`；只有一组的标签不写组标题（标题栏已经说了）；组间 1px `border` 分隔；第一组距分隔线 12，后面的组距上一条分隔线 20。行 = 标签列 120 + 24 间距 + 控件列铺满；标签 13.5 `text-primary`，说明 11.5 `text-tertiary`；行上下 padding 9。
- 语言与其他偏好自动保存（250ms 合并）。动作编辑由「完成」应用，草稿在当前应用进程内保留。

## 二、模型

一组，没有组标题。模型服务由 AI 助手通过辞达的命令行配置，这里只显示状态与「复制配置提示词」，见 `spec/configuration.md` §四。

## 三、动作

两组：语言、动作。

### 语言

- 一行「我的语言」，说明「其他语言都译成它」：控件列右侧一个宽 180 的输入框（右缘与下面的「编辑」按钮对齐），Inter 12.5，`surface` 底，聚焦 1.5px accent 描边，辅助功能名称「我的语言」。写什么都可以：语言、方言、地区写法或文体，如「简体中文」「粤语」「繁體中文（台灣）」「文言文」。默认「简体中文」（首选语言里有繁体中文时为「繁體中文」）。辞达的界面只有中文，所以不跟随系统语言：不少中文用户的系统是英文。
- 设置里只有这一个目标语言。我的语言译成哪门外语因场合而不同，写在面板的「翻译」上，在那里直接改（`spec/panel.md` §三），设置里不重复这一项，也不加说明：原文是我的语言时「翻译成」后面就写着它。
- 翻译方向由模型执行：请求带上我的语言、面板上写的外语与规则，模型判断原文属于哪一种。原处翻译 ⌥D 同样互译，但原文是不是我的语言由本机判断；整窗翻译只译成我的语言（`spec/translation-layer.md` §一）。
- 清空后失焦恢复默认。已经显示的结果不重新请求，下次 ⏎ 用新写法。
- 结果栏的字体随输出的文字而定：流式结果的开头足以判断是中日韩文还是西文时切到对应字体（`spec/panel.md` §七），不在请求前决定。

### 样例与面板

- 「翻译」标签改名「动作」（Lucide pen-line），两组：语言（「我的语言」，含义与位置不变）、动作。
- 动作组：组标题「动作」，右侧说明「拖动排序 · 首项默认」（caption，`text-tertiary`）。下面是缩小的面板，从上到下：
  - 样例：一段固定的原文，不可编辑（用户要的是同一段预置输入，不读剪贴板，也不用面板里的原文）。采用一段自然、略有冗余的工作沟通，包含时间、地点、改期原因与回复请求；不刻意制造病句，翻译、改进、精简、提取待办都能看出效果。固定原文为「想跟你同步一下，原定周五的分享会要改到下周三下午三点，地点还是二楼会议室。主要是因为演示还没准备好，有几处细节想再确认一下。如果这个时间不方便，麻烦明天中午前告诉我，我们再一起看看怎么安排。」。标签行左「样例」，右侧写明结果的来历（原生应用写「使用当前模型」，交互稿写明预置示例）。Inter 13 / 21pt 行高。
  - 动作栏：与面板同一个分段控件，列出全部动作，尾部一个 + 段；右侧一个按钮，「编辑 ⌘E」/「完成 ⌘↵」/「停止 ⌘.」，样子同面板的「停止」：文字 11.5 semibold，快捷键 11pt `text-tertiary`，间距 8；三种状态按钮同宽，不随快捷键长度跳动。
  - 纸面：`surface-paper`，所选动作在样例上的结果（衬线，同结果栏）与一行说明。
- 字体按内容职责统一：样例与无结果时的占位说明用 Inter 13、21pt 行高；编辑提示词用主面板输入的 Inter 16、26pt 行高，方便持续阅读与修改。两者中文都回退苹方、regular 字重；占位只降色，不放大，也不用衬线。控件与说明沿用界面的 Inter / 苹方，说明统一 11pt，动作与按钮 11.5pt；动作名称进入编辑时保持原字号与字重。只有模型实际生成的结果使用主面板的衬线正文（此处缩小到 15pt）。新建的加号使用 12pt 图标，不作为大字号文字。
- 打开时选中面板当前的动作；窗口高度随内容，展开与收起只由窗口外框做一次 150ms（`motion-height-ms`）ease-out，顶边不动。内部立即采用最终布局，不对整个动作组叠加 SwiftUI 高度、位移或淡入动画；样例与动作栏不动。不为最长的提示词预留空白。

### 浏览、编辑与应用

- 浏览：点一段只换纸面上的结果，不请求、不进入编辑。
- 编辑（「编辑」或 ⌘E）：提示词出现在纸面上方，是纸上的正文而不是输入框：上面一行 aside「提示词」（11，`text-tertiary`），正文 Inter 16 / 26pt 行高 `text-ink`，与主面板输入正文相同；编辑焦点只由 accent 色文字光标表达，不画整行绿色下划线。有上一次结果时，它留在 1px `border` 细线下作参照；还没有结果时，不显示分隔线、占位正文或空结果区，只在提示词下留一行「完成后预览 · ⌘↵」。所选段的名字原位可编辑，按实际字宽保持段宽；只有名字获得焦点时才出现 1px accent 下划线，写法同面板上改「翻译」的外语。
- 有改动时（名字或提示词与已应用的不同，或新建还没应用）：结果降为 `text-secondary`，说明「上次的结果 · 完成后更新」；其他段、+ 与拖动降为 45% 暂停，分段控件后面的提示位写「Esc 放弃」。没有改动时可以直接点别的动作，编辑随之结束，什么也不丢。
- 完成（「完成」或 ⌘↵）：应用名字与提示词，提示词收起。提示词与纸面上结果所用的不同时，在样例上生成一次：旧结果留着、降为 `text-secondary`，末尾光标呼吸，说明「正在按新提示词更新 · ⌘. 停止」，按钮为「停止 ⌘.」；同一时刻只有一次请求，新的取代旧的，只接收最后一次的结果。提示词没变则不请求。提示词为空或名字为空、重名时不应用，原因写在提示词下方。
- 失败、停止都在纸面原位说明，旧结果保留并降色：「已停止 · 仍是上次的结果」；请求失败写原因。未配置模型时说明需先配置模型服务；错误与取消都可以再次编辑并完成来重试。
- Esc：没有改动时只结束编辑；有改动时放弃这些改动，组下方写「已放弃修改 撤销」（新建写「已放弃新建「名字」 撤销」），点「撤销」或 ⌘Z 回到放弃前的编辑。
- 同一时刻只有一个编辑对象，没有按动作分开的草稿。关掉设置或切到别的标签再回来，这一份编辑原样还在；没有「已自动保存」一类的提示。应用退出后只保留已应用的动作；草稿、撤销与样例输出不持久化。

### 新建、改名、排序、删除

- 新建：点尾部 +，追加「新动作 N」并进入编辑，名字全选；⏎ 确定名字、光标到提示词；之后与编辑相同。应用之前它不出现在面板上。动作栏溢出时横向滚动；完成最后一个动作的编辑后滚到尾部，保留最后一个动作与 + 的可见性。
- 改名：编辑时直接改段里的名字；双击一段或 F2 是进入编辑并选中名字的快捷方式。
- 排序：拖动一段，落点处一条 2pt accent 竖线；⌥← / ⌥→ 移动聚焦的一段。顺序就是面板的顺序。
- 首项默认只用于通用入口：⌥A 唤起、⌥A 带入选区并生成、菜单栏「显示辞达」都从首项开始（取代「回到默认『翻译』」）。显式的翻译入口不跟随排序：截图翻译 ⌥S 与菜单「截图翻译」、原处翻译 ⌥D 总是用「翻译」。改进选区 ⌥F 仍执行内置「改进」策略；从动作栏删除「改进」只隐藏该段，快捷键仍使用默认改进提示词。
- 删除：编辑时纸面 aside 行右侧「删除动作」文字按钮；拖动时动作栏下方出现虚线框「拖到这里删除」，或聚焦一段按 ⌘⌫，是快捷方式。不确认；组下方写「已删除「名字」 撤销」，「撤销」或 ⌘Z 放回原位。
- 「翻译」不能删除，编辑时不显示它的「删除动作」入口：截图翻译与原处翻译这两个显式入口依赖它；对它删除时写「「翻译」用于截图翻译与原处翻译，不能删除」，拖动它时删除区写同样的话。其他动作，包括内置的「改进」，都可以删除。
- 内置动作的提示词与默认不同时，aside 行右侧另有「恢复默认」，填回默认提示词（仍由「完成」应用）。

- 预览调用当前模型服务，使用与主面板相同的提示词和请求构建，不进入主面板结果。生成期间保留旧结果，收到完整响应后替换；模型、语言或提示词变化后旧结果注明过期。自定义动作由提示词决定输出语言与格式，不强制保留原语言，也不套用翻译的纯文本输出规则。
- 翻译与改进以固定身份保存；改名不改变语言规则。已有用户的提示词迁移到同一动作列表。首项是默认，不另存默认标记；只有已应用的动作进入面板。

## 四、快捷键

「快捷键」标签的第一组，四个可录制的全局快捷键，互相不能相同；每一个都可以不设置：

| 行 | 说明 | 默认 |
| --- | --- | --- |
| 显示辞达 | 在任何应用里唤起 | ⌥ A |
| 截图翻译 | 框选屏幕文字并翻译 | ⌥ S |
| 原处翻译 | 加 ⇧ 翻译整个窗口（`spec/translation-layer.md`） | ⌥ D |
| 改进并替换 | 改进并替换选中文字 | ⌥ F |

- 键帽芯片（`surface-dim`，`radius-chip`，12 medium `text-secondary`）是一个按钮，显示当前组合。点击进入录制：芯片改为 `surface` 底、1.5px accent 描边、`text-tertiary`「按下新组合…」，说明变为「⌫ 不设置 · Esc 取消」；按下带 ⌘/⌥/⌃ 的组合立即保存并重新注册，Esc 或失焦取消；按下不带这些修饰键的按键不结束录制，说明改为「要带 ⌘、⌥ 或 ⌃」。注册失败（被系统、其他应用或另一个快捷键占用）保留原组合，说明变为「这个组合已被占用，换一个」。录制任一快捷键时所有全局快捷键都暂停，按下的组合只交给录制。
- 不设置（2026-09-30 决定）：录制时单独按 ⌫ 或 ⌦，立即注销这个全局快捷键并结束录制；带修饰键的 ⌫（如 ⌥⌫）仍是普通组合。未设置时芯片写「未设置」（`text-tertiary`），点击照常录制；组合不是默认值，所以左侧出现「恢复默认」。未设置的快捷键不参与「不能相同」，它原来的组合可以给别的快捷键。给只用其中一两个功能的人：只用截图翻译时清掉显示辞达与原处翻译。没有逐行开关，不弹确认。
  - 显示辞达未设置：菜单栏「显示辞达」仍能唤起面板，截图翻译照常把结果放进面板；带入选区只有全局快捷键会做，随之没有（菜单不读选区，见 `spec/panel.md` §一）。
  - 截图翻译未设置：菜单栏「截图翻译」照常可用。
  - 原处翻译未设置：原处翻译整个关闭，屏幕上的译文全部收回，整窗翻译停止（没有快捷键就没有办法再关掉它）；记住的窗口保留，重新设置快捷键后照常翻译（`spec/translation-layer.md` §二）。
- 原处翻译的组合不能带 ⇧（⇧ 留给翻译整个窗口）：录制时按下带 ⇧ 的组合不结束录制，说明改为「不能带 ⇧」。
- 组合不是默认值时，芯片左侧出现「恢复默认」文字按钮（12 medium `text-secondary`）。
- 设置里存着的组合就是用户的组合：默认值改变（显示辞达从 ⌥ Space 改为 ⌥ A）不迁移已有设置，这些用户仍用 ⌥ Space，芯片旁出现「恢复默认」，点它换成 ⌥ A。
- 菜单栏菜单里的「显示辞达」「截图翻译」跟随录制的组合，未设置时不显示按键（`spec/brand.md` §三）。

- 改进并替换未设置时，不注册此入口；停用会取消正在生成的改进任务。首次升级时若 ⌥F 已被其他辞达动作占用，保留原快捷键，改进并替换设为未设置。

## 五、权限

「快捷键」标签的第二组。两项系统权限都可选，各自服务几个功能，没有开关：授予即开启，在系统设置里取消即关闭。

| 行 | 说明 | 用途 |
| --- | --- | --- |
| 辅助功能 | 读取与替换应用文字 | ⌥ A 带入前台应用的选中文字（`spec/panel.md` §一）；原处翻译读取其他应用的文字（没有它时按 ⌥ D 只请求这项权限）；⌥ F 读取并替换选中文字 |
| 屏幕录制 | 截图翻译 | ⌥ S 冻结屏幕框选文字（原处翻译不用它：译文总是辞达的纸与墨） |

- 未授权：右侧「去授权」边框按钮（同「编辑」），点击弹出系统授权提示（屏幕录制同时打开「隐私与安全性 › 屏幕录制」；授权后 macOS 可能要求重新打开辞达）。已授权：右侧「已开启」（12 medium `text-secondary`）。
- 状态在窗口成为 key 时重新读取；辅助功能还在系统的允许列表变化时重新读取，不需要重启辞达。

## 六、通用

一组，没有组标题，下面是页脚。

- 开机启动：开关（accent 开 / `toggle-off` 关，系统 small 尺寸），失败时系统警告框说明。
- 更新：说明「每天自动检查」；右侧「检查更新」边框按钮（同「编辑」），没有开关（`spec/updates.md` §一）。后台检查发现新版本时，说明变为「新版本 <版本> 可以安装」，按钮变为「安装…」。行为见 `spec/updates.md`。通道随安装包决定，没有「测试版」开关。不能自己更新的构建（开发版，`spec/updates.md` §三）没有这一行，页脚写「开发版 <版本> (<构建号>) · <提交>」。
- 反馈：说明「报告问题或提建议」；右侧「去反馈」边框按钮（同「编辑」）。点击用默认浏览器打开 GitHub 上 Xuanwo/cida 的反馈 issue 表单（`.github/ISSUE_TEMPLATE/feedback.yml`），辞达自己不收集、不发送任何内容。链接只预填三项环境信息：辞达版本与构建号（开发版写页脚那一行）、macOS 版本、芯片架构；不带模型服务、地址、提示词或任何正在翻译的文字。表单只有「发生了什么 / 想要什么」一个必填文本框和这三项环境信息，用户在 GitHub 上看得到、改得了全部内容后自己提交；没有 GitHub 账号的用户由 GitHub 引导登录或注册。反馈入口只有这一处，开发版也有。
- 页脚居中，距上一行 26：字标（见 `spec/brand.md` §四）+「<版本> · 辞达而已矣」（caption，`text-tertiary`），间距 8。版本取应用包的 `CFBundleShortVersionString`（发版时由 tag 决定，默认 1.0）；未打包运行时只显示「辞达而已矣」。

## 七、强调色

只出现在：当前标签的图标、菜单当前项的 ✓、就绪点、聚焦描边、开关打开。
