# 更新

2026-09-25 确认：用 Sparkle 2 自动更新，更新文件托管在 R2 bucket `cida-releases`，地址 `https://cida-releases.xuanwo.io`。状态见 [`boards/lifecycle.html`](../boards/lifecycle.html)（更新面板）与 [`boards/settings-states.html`](../boards/settings-states.html)（设置「通用」页）。

## 一、检查与通道

- 每天自动检查一次更新清单 `https://cida-releases.xuanwo.io/appcast.xml`，没有关闭的开关：检查只取清单，装不装由用户点「安装…」决定。首次启动不询问是否允许自动检查；之前关掉过自动检查的，升级后恢复每天检查。
- 请求只取更新清单与安装包，不附带系统信息（Sparkle 的 system profiling 关闭）。
- 清单与安装包都用 EdDSA 签名，Cida 只接受签名有效的清单与安装包。
- 通道随安装包决定，没有开关：候选版本（tag `vX.Y.Z-rc.N`）的安装包也接收之后的候选版本与正式版；正式版只接收正式版。装上正式版后即回到正式通道。
- 开发构建（`swift run`）、自动化与 E2E 运行不检查更新。

## 二、发现新版本

- 用户主动检查（设置「通用」页的「检查更新」）：面板出现并显示检查、发现新版本、下载、安装的每一步，见 `spec/lifecycle.md` §五；不使用 Sparkle 自带的窗口。
- 后台定时检查发现新版本：由用户打开辞达时直接显示「发现新版本」面板；其余时候不弹面板、不抢焦点，只把设置「通用」页「更新」一行的说明变为「新版本 <版本> 可以安装」、按钮变为「安装…」，点「安装…」显示「发现新版本」面板。菜单栏菜单不显示更新（`spec/brand.md` §三）。
- 下载、校验签名、替换应用与重新打开由 Sparkle 完成，界面由辞达的面板呈现；设置在更新会话结束后恢复原样。

## 三、开发版

开发版（`CIDA_VARIANT=dev scripts/build-app.sh` 或 `scripts/run-dev.sh` 构建的「辞达 Dev」）是和正式版并排安装的另一个应用：bundle id `com.xuanwo.Cida.dev`，设置、API Key 与系统权限各自一份，不连更新清单、从不自己更新，版本取仓库最近的正式 tag 与提交数（和发版的算法相同），不用编造的版本号。它的菜单栏菜单最上面多一行不可点的「开发版 1.2.0 (170) · c243eb7」（提交带 + 表示构建时有未提交的改动），接一条分隔线（`spec/brand.md` §三）。设置「通用」页的页脚同样写这一行，没有「更新」一行。两个版本注册同样的全局快捷键，同一时间只运行一个：`scripts/run-dev.sh` 先退出正式版再启动开发版，`scripts/run-dev.sh stop` 反过来。之前在本机用正式版的 bundle id 装开发构建时，只能编一个更高的版本号（如 1.99.0）挡住更新，而且开发时的实验设置会留在正式版里。

## 四、保留

- 更新清单里正式版与候选版本各保留最新两个构建；每次发布新版本后，清单不再列出的版本连同它的 zip 与 DMG 从 R2 删除。保留两个，是为了让已经发现上一个版本、尚未安装的用户仍能下载到它。
- `latest/Cida.dmg` 始终是最新正式版；每个版本的 DMG 另外长期附在 GitHub Release 上。
